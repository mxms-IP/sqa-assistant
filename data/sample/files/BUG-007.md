# BUG-007.md

**ID:** BUG-007  
**Title:** Delivery timeline query redirects user to order tracking page instead of answering inline  
**Severity:** Medium  
**Priority:** Medium  
**Status:** Open  
**Reported by:** Riya Menon  
**Build:** v0.9.2  
**Environment:** Chrome 124, desktop, macOS Sonoma

---

**Steps to reproduce:**
1. Open chatbot on the Samsung Galaxy S22 product page (product not yet added to cart).
2. Type: "When will this be delivered if I order today?"

**Expected result:**  
Per Technical Requirement 3, the chatbot should provide the estimated delivery timeline directly within the chat interface for a product the user is currently viewing (pre-purchase context).

**Actual result:**  
The chatbot responds with: "To check delivery status, please visit your Orders page." and provides a hyperlink to the order tracking section. The user has not placed an order — this is a pre-purchase query. The chatbot is treating a delivery timeline question as an order tracking request, which is a Non-Goal misclassification.

**Related PRD requirement:** Technical Requirement 3; PRD Non-Goals (order tracking is out of scope, but pre-purchase delivery estimates are in scope)  
**Related test case:** TC-008

**Notes:** The NLP model appears to be conflating "delivery timeline" with "order tracking." Data Science to add disambiguation training for pre-purchase vs post-purchase delivery queries.
