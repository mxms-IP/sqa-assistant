# BUG-009.md

**ID:** BUG-009  
**Title:** Cross-device session not restored — conversation history missing when switching from mobile to desktop  
**Severity:** Critical  
**Priority:** Critical  
**Status:** Open  
**Reported by:** Riya Menon  
**Build:** v0.9.2  
**Environment:** Mobile: Samsung Galaxy S22, Android 14, Chrome Mobile → Desktop: Chrome 124, Windows 11

---

**Steps to reproduce:**
1. Log in to the same Amazon account on a Samsung Galaxy S22 (Android 14, Chrome Mobile).
2. Open chatbot on the Samsung Galaxy S22 product page.
3. Ask at least two questions (e.g., "What is the RAM?" and "Is there an EMI option?").
4. Note the conversation thread.
5. On a separate desktop machine (Chrome 124, Windows 11), log in with the same account.
6. Navigate to the Samsung Galaxy S22 product page.
7. Open the chatbot.

**Expected result:**  
Per Technical Requirement 4, the session should continue across devices. Conversation history from the mobile session should be visible and the chatbot should maintain context.

**Actual result:**  
The chatbot opens as a completely new session on desktop. No conversation history is loaded. The user must start from scratch. Session token from mobile is not being recognised on desktop login.

**Related PRD requirement:** Technical Requirement 4  
**Related test case:** TC-010

**Notes:** This is a **release blocker**. Critical severity because it is a core differentiating feature per Technical Requirement 4. Engineering confirmed the session persistence service is not writing tokens to the shared session store in v0.9.2 — only writing to a local device cache. No ETA provided yet.
